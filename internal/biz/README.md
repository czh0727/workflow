# 业务层

业务层只包含领域对象（DO）、用例、业务错误和仓储接口，不依赖 Proto、SQL、存储驱动或外部 SDK。仓储接口由业务层声明，由数据层实现。

## 职责

- 根据领域规则校验输入，并编排业务操作。
- 定义仓储接口和列表查询选项。
- 将缺少资源、参数错误和内部错误映射为可识别的业务错误。
- 不在这里组装 SQL、不读取配置、不调用 HTTP 客户端。

领域对象必须保持纯粹：不放 Proto 类型、数据库标签或驱动专用类型。需要外部数据时，通过仓储接口获取；需要转换存储结构时，在 data 层完成。

## 测试

业务层测试使用假的仓储接口，验证规则和用例行为。新增资源时先定义 DO、仓储接口和用例，再由数据层实现接口。多个相近场景优先使用表驱动测试。
