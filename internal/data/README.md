# 数据层

数据层实现 `biz` 定义的仓储接口。它是理解业务的外部数据源适配器，而非传统的 DAO 层。
数据库、缓存、远程服务和 Temporal 的细节都保留在此包内部。

## 职责

数据层可以：

- 编排一个或多个 sqlc 查询，完成仓储操作；
- 调用完成仓储操作所需的远程服务；
- 将多个表的数据组装成 `biz` 所需的结构；
- 将持久化模型转换为 biz 实体；
- 将数据库、驱动和远程服务错误映射为 biz 错误；
- 在缺少关联数据时报告内部一致性错误，而不是默默返回不完整的数据。

核心业务决策和不变量属于 `biz`，不属于 data。

## 依赖边界

- 仓储实现之间不得依赖或互相调用。例如，`executionRepo` 不得调用 `workflowRepo`。
- 仓储实现共享 `Data` 持有的客户端，可直接调用所需的数据库或远程服务客户端。
- `biz` 不得依赖 sqlc 生成类型、SQL 行、表结构或外部 SDK 类型。
- sqlc 生成代码和外部 SDK 客户端是 data 的实现细节，不得通过仓储接口暴露。

## 查询规则

- 优先使用直接的命名 SQL 查询和清晰的仓储代码。
- JOIN 需要明确批准。只有具体查询已获明确批准，且 JOIN 能明显简化实现时才使用。
- 未获批准时，使用 `ANY($1::type[])` 等批量查询加载关联行，并在 data 中组装，
  不得引入 N+1 查询。
- 在 Go 中组装结果之前，先在 SQL 中完成过滤、稳定排序和分页。
- 根据真实的过滤、JOIN 和排序路径添加索引。PostgreSQL 外键不会自动为引用列建立索引。
- 保持索引精简。只有查询同时使用联合索引最左侧键，或需要其完成排序时才使用联合索引。
- 索引选择很重要时，使用代表性数据执行 `EXPLAIN`。存在索引不意味着 PostgreSQL
  会在每种数据分布下都选择它。

## 数据库目录

数据库相关文件统一放在 `db/` 下，让 sqlc 始终作为 Kratos 数据层的内部实现细节：

- `db/migrations/` 保存带版本的结构迁移 SQL。文件名使用 `000001_description.sql`
  等补零格式；不需要迁移工具注解。
- `db/queries/` 保存供 sqlc 使用的命名查询。
- `db/sqlcgen/` 通过 `make sqlc` 生成，禁止手工编辑。

以上路径以模块根目录的 `sqlc.yaml` 为准。

不要为生成代码或导入的第三方包编写单元测试。
